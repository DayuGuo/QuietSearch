# 实施决策

2026-10-22。原始设计包保持原样，代表 v1.1 设计历史。本文件记录用户后续要求和实施取舍。

1. 用户明确要求检索记录和每日检索量，覆盖旧版“不存搜索历史”。默认只在当前浏览器 localStorage 保存检索词、时间、模式、完成状态和结果数；最多 200 条、30 天。可以暂停新增、删除单条、清除全部。没有云端历史数据库。
2. 每日统计独立于历史，最多保留 90 天，记录应用请求数、成功搜索、返回结果条数、AI 请求和完整流报告的 tokens。日期是请求发起时浏览器本地日期。统计不是供应商账单，不包含其他设备、丢失的流用量，也不保证跨标签页原子计数。
3. 密钥不进入持久存储。设置中的粘贴、测试和使用是不同动作，测试和保存均不会自动执行待搜索内容。
4. 选择历史记录只填入搜索框；再次提交才产生新请求。历史不保存网页结果或 AI 回答，避免持久化大量第三方内容。
5. 参考 Kagi 的搜索优先、清晰结果层次、克制导航和按需回答。保留 QuietSearch 工作名，不复制 Kagi 品牌、资产、账户系统、搜索分类或供应商能力。
6. 继续单 Worker + Static Assets。无数据库、缓存、全文抓取、Agent、多供应商框架和跨设备同步。
7. 列表来源摘要优先 summary，缺失时用 snippet；两者都为空的结果仍可展示，但不送入摘要。最多 6 条来源。无状态摘要路由接受客户端来源，并不证明来源来自之前的 Search；只适用于 BYOK 或受认证私人模式。
8. 一次提交一次搜索、一次自动摘要是前端流程约束，不是全局恰好一次交易保证。取消尽可能传递到上游，已处理部分仍可能收费。
9. Node 24 是文档、.nvmrc、engines 和 CI 的基准。兼容日期使用已安装 workerd 支持的 2026-10-19；不能机械地设置为今天而导致本地运行失败。
10. 生产 CSP 禁止内联脚本与样式。开发环境仅为 Vite 的热更新注入放宽对应指令；生产构建移除该分支，并有 HTTP 级测试确认。
11. 用户要求更多结果和可理解的排序。网页每次请求最多 50 条，默认展示 10 条，按钮逐批展开同一次响应。原 10/20 偏好作为展示批大小保留。没有后台追加搜索、伪分页或自动查询改写。
12. 综合评分和来源等级只作为供应商信号展示，不作为事实准确率。默认保留上游顺序；可在本地重排全部已获取结果。排序/展开不改变引用编号、摘要来源或每日计数，最多仍使用 6 条来源生成回答。
